## 2. 通用列表页模式

几乎所有业务列表页（除 KPI 报表外）都遵循同一结构：

```
┌─────────────────────────────────────────────────────────────────┐
│ 筛选条件行（2-4 个字段 + 高级筛选/更多筛选）                       │
├─────────────────────────────────────────────────────────────────┤
│ [+ 新建XX] [↓ 导出/下载] [其他批量操作]                              │
├─────────────────────────────────────────────────────────────────┤
│ 表格：表头 + 行（最后一列固定为「操作」）                            │
│ 操作列常见链接：详情 / 编辑 / 撤销 / 催办 / 重新发起 / 导出ID          │
├─────────────────────────────────────────────────────────────────┤
│ 15条/页  共 N 条  < 1 2 3 … 67 >  前往 1 页                       │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 操作列（行级）CRUD

| 操作 | 命名约定 | 出现位置 |

| 任务记录 | "任务记录" | 开户明细 |
| 已完成 | "已完成"（灰色） | 开户明细 |
| 期初余额 | "期初余额"（绿色） | 集团管理 |

### 2.3 筛选区字段

通用筛选条件模式：
- **文本搜索**：客户名称 / 集团名称 / 政策名称 / 申请人 / 创建人 / 任务ID
- **下拉选择**：状态 / 审批状态 / 媒体平台 / 付款方式 / 服务商池
- **日期区间**：申请日期 / 创建日期 / 设置日期（开始日期 - 结束日期）
- **多选标签**：开户状态 / 任务类型（多个）
- **「更多筛选」按钮**：折叠高级筛选

- 数据表格（员工 KPI 透视表）：
  - 行：员工姓名 + 汇总统计（KPI目标/总消耗/完成率）+ 每个媒体细分（头条-AD/头条-千川/头条-本地推/小红书-品牌/小红书-聚光/微博-新客/微博-框架/快手-AD/腾讯-广点通）

#### 3.6.5 变更记录 `/changeLog`

**列表列**（9 列）：修改类型｜媒体平台｜设置日期｜归属来源｜修改前｜修改后｜变更说明｜创建人｜提交时间

**特点**：
- 纯只读日志页（无新建/编辑/删除按钮）
- 修改类型枚举：部门KPI设置 / 员工KPI设置
- 「修改前」/「修改后」展示数值差异
- 「变更说明」格式：【修改人】为【归属部门】在【媒体】修改了...

**筛选条件**：创建人 / 媒体平台 / 创建时间（开始-结束）

## 8. 设计原则提炼

从 PC 端抽象出的设计原则（可迁移到 App）：

1. **CRUD 一致性**：所有列表页都是「筛选+按钮+表格+分页」四件套
2. **操作就近**：行级操作（详情/编辑/撤销）放在最右列
3. **状态颜色化**：待处理（黄）/通过（绿）/驳回（红）/撤回（灰）
4. **必填可视化**：弹窗表单加红星 `*`，placeholder 给填写示例
5. **批量操作**：复选框 + 顶部批量按钮
6. **审批流**：每条业务线都有「审批状态」字段，支持状态机流转
7. **审计日志**：KPI 类敏感操作自动写入「变更记录」
8. **导出友好**：每个列表都有「下载/导出」按钮
9. **多维分析**：KPI 报表采用 Tab 切换 + 透视表
10. **服务化**：客户/集团/政策通过 ID 关联，便于数据一致性
